# Правила верстки

Правила для продуктового UI. Код API и папку «Прототип» по этим правилам не переписываем.

## 1. HTML, CSS и JS без сборщиков и фреймворков

Продуктовый UI — обычные страницы в `web/`, не React и не бандлер. Новый экран — HTML + CSS + JS, без npm-сборки «под продукт». Vite только раздаёт страницы и проксирует `/api`.

## 2. Один экран прототипа — одна страница в `web/`

Фрейм из карты не склеивать с соседним в один файл. Empty-состояния того же шага (нет слотов, только дизайн) остаются вариантами этой страницы, если в карте это один шаг.

## 3. Все обращения к серверу через `web/js/api.js`

Страница не вызывает `fetch` сама: только функции из этого модуля. Так проще менять сессию, ошибки и базовый URL в одном месте. Внутри страниц запросов быть не должно.

## 4. Цвета, шрифты и размеры только из `web/tokens.css`

В стилях экрана — `var(--…)`. Новых hex, кеглей и отступов не добавляем. Если токена нет — это дыра системы, не «подобрать похожее».

## 5. Папку `server/` не трогаем

Не хватает эндпоинта или поля — сначала сказать человеку. Не дописывать API «заодно с версткой».

## 6. Папку «Прототип» не меняем и не переименовываем

Это образец экранов, не рабочая копия. Смотреть, не править файлы внутри.

## 7. Ошибку API показываем текстом на экране

Сообщение из ответа (`error.message`) видно клиенту рядом с формой или списком. Одной консоли недостаточно.

## 8. Экраны мастера и администратора пока не верстаем

Клиентский срез: лендинг, авторизация, запись, кабинет, служебные. Админ-панель появится в следующей итерации.

---

Перед версткой нового экрана откройте его строку в [docs/ui-map.md](ui-map.md): что показывает, откуда данные, куда ведет.
