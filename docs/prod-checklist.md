# Чек-лист проверки после публикации

Сокращение из [`docs/test-checklist.md`](test-checklist.md): только сценарии, на которые мог повлиять переезд на сервер (часовой пояс сервера, HTTPS и cookie, переменные окружения из панели, задержка сети). Полный чек-лист этим файлом не заменяется. Проверять вручную на опубликованном домене с HTTPS.

Критерии отбора: серверное время / TZ студии; Secure-cookie на HTTPS; env из панели Coolify; RTT и гонки по сети.

База проверки: `https://nogotochki-test.ru` (частично также `http://159.194.227.249:3000`). Подробные протоколы: [`docs/prod-check-results/`](prod-check-results/).

## Как допройти невыполненные сценарии

Общий блокер для A3, A14, A15 и админ-половин C11/S4: на проде **нет учётки администратора**. Seed `admin@nogotochki.test` / `DevAdmin123!` и `client@nogotochki.test` в серверной БД отсутствуют (login → 401). `npm run seed:dev` на production **нельзя** (`NODE_ENV=production` его запрещает и он не для живых данных).

### 0. Сначала завести администратора на проде

Выберите **один** способ.

**Вариант A — bootstrap из Coolify (предпочтительный)**

1. В панели Coolify у сервиса откройте Environment Variables.
2. Задайте (пароль ≥ 8 символов, не из git):
   - `BOOTSTRAP_ADMIN_EMAIL` — почта будущего админа
   - `BOOTSTRAP_ADMIN_PASSWORD` — пароль
3. Перезапустите контейнер. При старте, если в БД ещё нет роли `administrator`, создаётся эта учётка (`server/src/db/bootstrap-admin.js`).
4. Войдите на `https://nogotochki-test.ru/auth.html` этой почтой/паролем → должно открыться `/admin` (список дня, разделы Записи / Услуги / Мастера).
5. После первого успешного входа переменные `BOOTSTRAP_ADMIN_*` можно убрать из env (учётка уже в БД).

**Вариант B — уже есть админ, но другой пароль**

1. Возьмите фактические `BOOTSTRAP_ADMIN_EMAIL` / пароль из Coolify (или тот, которым реально создавали админа).
2. Не подбирайте пароль; не запускайте `seed:dev` на томе с живыми записями.

Проверка готовности: `POST /api/auth/login` админом → **200** и cookie `session` (Secure на HTTPS); `GET /admin` без редиректа на auth.

Дальше — по сценариям.

### A3. Вход администратора

После шага 0:

1. Откройте `https://nogotochki-test.ru/auth.html`.
2. Войдите админом (учётка из шага 0).
3. Ожидайте: сразу `/admin`, заголовок вроде «Записи»; в шапке ссылки Записи / Услуги / Мастера; 403 нет.
4. В DevTools → Application → Cookies: у `session` флаги **Secure**, HttpOnly.
5. Запишите в [`A3.md`](prod-check-results/A3.md) и смените статус на **pass**; обновите колонку «Результат» в таблице выше.

### A14. Блокировка времени мастера `[2 окна]`

Нужны A3 (админ) и два окна браузера.

1. **Окно B (админ):** войдите → `/admin` → выберите мастера и день, где у гостя ещё есть свободные старты (например день с слотами 10:00–18:00).
2. Создайте блокировку на известный интервал (как в полном чек-листе: перерыв, напр. 12:00–14:00). Ожидайте flash вроде «Время заблокировано…».
3. **Окно A (гость/клиент):** запись → шаг 3 (дата/время) → тот же мастер и день → обновите/переоткройте день.
4. Ожидайте: старты внутри блока **не** в списке свободных (пусто или без 12:00/13:00 и т.п.). Можно сверить `GET /api/masters/:id/availability?…`.
5. Cleanup: в админке удалите time-block (`DELETE` / кнопка снятия блока), чтобы не оставлять дыру в расписании.
6. Статус → **pass** в [`A14.md`](prod-check-results/A14.md) и в таблице.

### A15. Пустой день в списке записей

После A3:

1. В `/admin` выберите гражданскую дату **без** визитов (удобно далёкая дата в будущем, если ближайшие дни уже заняты тестовыми записями).
2. Ожидайте: empty списка («Пока пусто» / «На этот день записей нет»); **нет** клиентского CTA «Записаться» как у пустого кабинета (админские «Заблокировать время» / «Новая запись» — норма).
3. Статус → **pass** в [`A15.md`](prod-check-results/A15.md) и в таблице.

### C11 (доделка). Студия подтверждает предоплату

Клиентская часть уже **pass**. Не хватает только админского подтверждения.

1. Выполните шаг 0 (админ).
2. Найдите запись в статусе «ожидает предоплату» (например созданную при проверке C11: клиент `prodcheck-c11-…`, слот 2026-09-23 10:00) — в `/admin` на эту дату.
3. Нажмите подтверждение предоплаты (админский UI / соответствующий API).
4. Откройте кабинет того же клиента (или детали записи): статус станет «подтверждена» / «Запись подтверждена»; уличного адреса по-прежнему нет, если `exact_address` пустой.
5. Допишите в [`C11.md`](prod-check-results/C11.md) подшаг admin confirm → pass; в таблице можно убрать пометку «admin confirm blocked».

### S4 (доделка). Выход закрывает админку

Клиентская половина уже **pass**.

1. Войдите админом → откройте `/admin`.
2. «Выйти» в шапке.
3. Снова откройте `/admin` → редирект на `auth.html?next=%2Fadmin` (или аналог); списка записей нет.
4. `GET /api/auth/me` → 401; cookie `session` сброшена.
5. Допишите в [`S4.md`](prod-check-results/S4.md); в таблице — полный **pass**.

### Не обязательно, но полезно

- **Тестовый клиент:** seed `client@nogotochki.test` на проде нет; для ручных ретестов регистрируйте новую почту или заведите постоянного тестового клиента вручную (не через `seed:dev` на production).
- **C10** в этой выгрузке отмечен **pass** (успешный вход через Яндекс принят). Env и ветки отмены/ошибки на проде уже были подтверждены ранее.
