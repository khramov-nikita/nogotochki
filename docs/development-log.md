### C17. Нет empty «Нет свободного времени» на переносе

- **Сломано:** дни без окон на переносе нельзя было выбрать; empty не показывался.
- **Причина:** в `cabinet-reschedule.js` пустые дни получали `disabled`, клик игнорировался.
- **Исправление:** в горизонте пустые дни кликабельны (вид unavailable без `disabled`); при смене дня сбрасывается выбранный слот.

### S3. Неверный текст при конфликте слота на confirm

- **Сломано:** после чужого занятия слота на подтверждении показывалось «Резерв истек…» вместо «Это время уже занято».
- **Причина:** purge стирал холд до проверки занятости слота.
- **Исправление:** снимок холда до purge + `SLOT_TAKEN`, если слот занят (`holds.js`); fallback в `booking-review.js`, если холд уже стёрт.

### G3. Нет подарочного сертификата / «Условия в студии»

- **Сломано:** на лендинге не было карточки сертификата и кнопки «Условия в студии».
- **Причина:** в `seed-dev.js` не было `gift_certificate`.
- **Исправление:** в seed-dev добавлен `gift_certificate` (`is_bookable = 0`, цены 3000/5000, срок 6 мес.); услуга дописана в локальную SQLite. UI уже различал CTA по флагу.

# Журнал разработки — подготовка к серверу (2026-09-15)

Проект подготовлен к запуску в контейнере: добавлены `Dockerfile` (Node 24.19.0) и `.dockerignore` (зависимости, локальная база, `.env`, `.git` в образ не копируются).

Файл базы живёт отдельно от кода, который при обновлении контейнера стирается. Путь берётся из настройки `DATABASE_PATH` (не зашит в логику). Локально по умолчанию — `data/nogotochki.sqlite` от корня репозитория; в Docker по умолчанию — `/data/nogotochki.sqlite` (том на сервере). Папка под файл создаётся сама при первом запуске, если её ещё нет.

Миграции применяются приложением при старте (`applyMigrations` до `listen`); уже записанные в `schema_migrations` повторно не выполняются. Вручную `npm run migrate` на сервере не нужен.

## Настройки на сервере

|---|---|---|

| `PORT` | Только если порт не 3000 | `3000` |

| `SESSION_DAYS` | Нет | `30` |

| `YANDEX_OAUTH_STUB` | Не включать на сервере | `0` (выкл.) |

| `DEV_*_PASSWORD` | Нет на сервере | только для локального `seed:dev` |
| `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` | Да на пустой БД в Coolify | нет в git; создаёт первого администратора при старте |

# Журнал разработки — сессия на HTTP-проде (2026-09-21)

### Регистрация / вход не держали кабинет на Coolify

- **Сломано:** после «Зарегистрироваться» страница снова открывала вход/регистрацию, кабинет не открывался.
- **Причина:** при `NODE_ENV=production` cookie сессии всегда ставилась с флагом `Secure`. Сайт на Coolify открыт по **HTTP**, браузер такую cookie не сохраняет → `GET /api/auth/me` даёт 401 → редирект на auth.
- **Исправление:** `shouldUseSecureCookies(req)` в `server/src/http/cookies.js` — флаг `Secure` только при реальном HTTPS (`req.secure` или `x-forwarded-proto: https`). Используется в login/register/yandex/logout. Тест: `server/src/http/cookies.test.js`.
- **Проверка:** после деплоя коммита `3020063` регистрация на `http://159.194.227.249:3000` открывает кабинет и сессия сохраняется после обновления страницы.
