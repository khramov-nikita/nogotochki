# Карта экранов

Сверка фреймов Figma (`Screens`, файл `PN8kfs5KAmLwwqZIKmnAOG`) с живым HTTP API в `server/src/http/` и страницами `web/*.html`. Черновой hash-UI (`web/src/`, `web/test.html`) сюда не входит. Папки `Прототип/` в репозитории нет — имя экрана = имя фрейма. Админских кадров в макете нет: имена в разделе «Администратор» заданы по той же схеме, без node-id.

Источники: `cloud.md`, `Путь клиента.md` §3, `docs/db-schema.md` §2, `docs/database.md` §HTTP API, роутеры `server/src/http/routes/`.

Экраны мастера не включены. Административные экраны — в разделе «Администратор».

## Общие переходы шапки и футера

Не повторяются в каждой строке.

- Guest (лендинг, каталоги, карточка мастера, шаги 1–3 записи, проверка гостя, «Резерв истёк», служебные, политика): логотип → `Landing — Ноготочки`; «Услуги» → `Catalog — Услуги`; «Мастера» → `Catalog — Мастера`; «Записаться» → `Booking — 1 Услуги`; «Войти» → `Auth — Вход`; футер «Политика конфиденциальности» → `Legal — Политика конфиденциальности`.
- Auth-фреймы: ссылки «Войти» в шапке нет. Логотип → лендинг. Primary — только в форме.
- LoggedIn («вход выполнен», «Готово», «Слот занят», кабинет): вместо «Войти» — «Кабинет» → `Cabinet — Активные`. Выход — `POST /api/auth/logout`, отдельного фрейма нет.

Любой закрытый запрос с 401 → `Error — Сессия истекла`. Любой 500 → `Error — Сервер`. Неверный URL → `Error — 404`.

Формат строки ниже: фрейм — показывает | данные | кнопки | переходы. Таблицы в каждом разделе — та же карта в четыре колонки.

## Запись

Черновик гостя: состав услуг в UI + `hold_token` в `localStorage`; источник сводки на шаге 4 и после auth — `booking_holds` + `booking_hold_services`. Сертификата в степпере нет. Дизайн ногтей — добавка (`is_addon`). «Назад» и клик по пройденному шагу возвращают назад; будущие шаги закрыты. Смена услуг/мастера так, что слот не подходит, сбрасывает резерв (`DELETE /api/holds/:token` или новый `POST /api/holds` с тем же `hold_token`).

## Администратор

Кадров в Figma нет: имена ниже — те же правила, что у клиентских фреймов, без node-id. Черновой hash-UI (`web/src/pages/admin.js`) сюда не входит.

Вход — тот же `Auth — Вход`; после успеха `GET /api/auth/me` с `is_admin: true` ведёт в `Admin — Записи`. Строка auth в клиентской карте не меняется.

Общие переходы шапки (не повторяются в каждой строке): `Nav Header` LoggedIn; «Записи» → `Admin — Записи`; «Услуги» → `Admin — Услуги`; «Мастера» → `Admin — Мастера`; выход — `POST /api/auth/logout`. 401 → `Error — Сессия истекла`. 403 `FORBIDDEN` отдельного кадра нет. Не-админ на эти страницы не попадает. Отмены и переноса чужих визитов нет.

Статус `rescheduled` на деталях — то же тело, что у «ожидает предоплату», с кнопкой подтверждения. Отдельного кадра нет.

| Карточки лендинга и число мастеров | можно собрать из нескольких запросов: `GET /api/services` + `GET /api/masters` | Прайс и мастера уже в API; число мастеров — длина массива, отдельный счётчик не нужен |
| Баннер сертификата в `Catalog — Услуги` | это не данные, а обычный контент страницы | Текст «не слот, купить в студии» — копирайт пути клиента; карточка сертификата уже в `GET /api/services` (`is_bookable`, `price_rub_alt`) |
| `Master — Карточка` без `GET /api/masters/:id` | можно собрать из нескольких запросов: `GET /api/masters` (найти `id`) + `GET /api/services` + `GET /api/masters/:id/availability` с `service_ids` этой карточки | Отдельного GET по id нет, но список отдаёт `id`, `cover_path` и `service_ids`; availability без `service_ids` не вызывается |
| `Legal — Политика конфиденциальности` | это не данные, а обычный контент страницы | Юридический текст в макете; HTTP `content_pages` нет |
| `Auth — Письмо отправлено`, `Auth — Новый пароль`, `Auth — Пароль изменён` | убрать элемент из верстки | Ссылку «Забыли пароль» и три кадра не подключать: reset-HTTP нет, имитировать письмо нельзя |
| `Cabinet — Профиль` | значение брать из API (`GET /api/auth/me`), а поля смены пароля убрать из верстки | Почта и имя уже в `me`; смены пароля в API нет |
| `Cabinet — Уведомления` | убрать элемент из верстки | `GET /api/notifications` нет; собирать ленту из записей — выдумывать события |
| `Cabinet — Правила отмены и переноса` | это не данные, а обычный контент страницы | Текст из макета без дедлайнов; HTTP страницы нет |

## Эндпоинты, которым не нашлось клиентского экрана

| Находка | Решение | Почему |
|---|---|---|
| `GET /api/health` | оставить как есть | Проверка процесса, не страница клиента |
| `POST /api/auth/logout` | добавить кнопку на существующий экран | Выход в шапке LoggedIn, отдельный фрейм не нужен |

Админские маршруты `/api/admin/*` — в разделе «Администратор», не в этой таблице.

Не считаются «без экрана»: `POST/GET/DELETE /api/holds`, `POST /api/appointments`, списки и детали записей, cancel/reschedule, catalog/availability, login/register/`me` — они закрывают степпер, кабинет и empty `HOLD_EXPIRED` / `SLOT_TAKEN`.

## Что на стороне экрана решить нельзя

- восстановление пароля
- смена пароля в профиле
- лента уведомлений

## Административные экраны, для которых в API не хватает данных

- `Admin — Детали / ожидает предоплату`, `Admin — Детали / подтверждена` — нет `GET /api/admin/appointments/:id`.
- `Admin — Услуга / правка` — нет `GET /api/admin/services/:id`.
- `Admin — Мастер / правка` — нет `GET /api/admin/masters/:id`.
- 403 «недостаточно прав» — в макете нет кадра; API отдаёт JSON `FORBIDDEN`.
- В админ-API нет: `studio_settings`, `studio_closures`, `master_time_blocks`, `content_pages`, список клиентов, выдача ролей, `masters.client_id`, отмена и перенос чужой записи.

## Административные эндпоинты, для которых не нашлось экрана

- Маршруты `/api/admin/appointments`, `/api/admin/services`, `/api/admin/masters` закрыты разделом «Администратор».
- `overlap_override` на `POST /api/holds` и `POST /api/appointments` (роль администратора; не `/api/admin/*`) — отдельного экрана нет; клиентский степпер флаг не показывает.
