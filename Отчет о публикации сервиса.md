## Разбор одной поломки публикации

**Что видел:** после «Зарегистрироваться» на `http://159.194.227.249:3000` снова открывался экран входа/регистрации, кабинет не удерживался; `GET /api/auth/me` отвечал 401.

**Чем оказалось:** при `NODE_ENV=production` cookie сессии всегда ставилась с флагом `Secure`. Сайт на Coolify в тот момент открывался по HTTP, браузер такую cookie не сохранял. Версия «сломалась регистрация» отпала после проверки Set-Cookie и `/api/auth/me`: причина — `Secure` на не-HTTPS.

**Как починил:** в `server/src/http/cookies.js` флаг `Secure` ставится только при реальном HTTPS (`req.secure` или `x-forwarded-proto: https`); задеплоен коммит `3020063`.

**Как убедился, что починилось:** снова прошёл регистрацию на `http://159.194.227.249:3000` — открылся кабинет, после обновления страницы сессия сохранилась. Позже на `https://nogotochki-test.ru` в C1/C11 cookie с `Secure`, кабинет после регистрации держится.

**Чем эта поломка отличалась от тех, что случались на своем компьютере:** локально сервис обычно идёт без связки «production + чистый HTTP за прокси Coolify», поэтому cookie с `Secure` на HTTP там не ломала вход; сбой проявился только после публикации на сервере.

## Решение по персональным данным

**Режим работы сервиса:** учебный на вымышленных данных (и собственных данных разработчика)

**Что сделано, чтобы не собирать чужие данные:**
- решение зафиксировано в журнале разработки: чужие настоящие данные не заводим, реальных клиентов не приглашаем;
- отдельной предупреждающей плашки на главной нет; в футере есть ссылка «Политика конфиденциальности»;
- в базе на момент копии с сервера (21.09.2026) — тестовые учётки проверки (`prodcheck-…`, `…@nogotochki.test`, `…@test.local` и т.п.) и собственный вход через Яндекс при C10; seed `client@nogotochki.test` на проде отсутствует;
- адрес `https://nogotochki-test.ru` использовался для учебной публикации и проверки, живым клиентам студии не раздавался.

**Что будет с сервером и данными после защиты:**
- сервер в Coolify остановить и удалить после защиты;
- файл базы на томе (`/data/nogotochki.sqlite`, том `nogotochki_data`) удалить вместе с сервисом; локальную копию `nogotochki.sqlite` с компьютера тоже удалить;
- домен `nogotochki-test.ru` (BeGet, оплачен до 15.09.2027) после защиты не использовать для сбора данных; DNS/прокси снять или не продлевать регистрацию по истечении срока.
