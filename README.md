# Ноготочки

Веб-сервис записи в бьюти-студию: клиент выбирает услуги и мастера, резервирует слот и управляет визитом. Оплаты на сайте нет.

В репозитории уже есть HTTP API и черновой тестовый интерфейс, чтобы проверить API в браузере. Это не продуктовый дизайн (не Figma и не v0).

Репозиторий: https://github.com/khramov-nikita/nogotochki (private, ветка `main`).

## Что нужно установить заранее

На компьютере ничего из проекта ставиться само не будет. Нужны две программы:

1. **Git** — [git-scm.com](https://git-scm.com/downloads). После установки закройте и снова откройте терминал.
2. **Node.js 22.16 или новее** (подойдёт 22 LTS не ниже 22.16 или 24) — [nodejs.org](https://nodejs.org/). Отметьте установку npm, если установщик спрашивает.

Проверка в терминале:

```bash
git --version
node -v
npm -v
```

`node -v` должен показать `v22.16…` или `v24…`. Версии 18, 20 и 22.15 и старше **не подойдут**: база идёт через встроенный `node:sqlite`.

Windows: команды ниже работают в PowerShell. Если `npm` не находится — перезапустите терминал после установки Node.

## Запуск с нуля

Нужны **два терминала**: в одном API, в другом страница. Не открывайте `web/index.html` двойным щелчком — запросы к API так не пойдут.

### 1. Скачать код

```bash
git clone https://github.com/khramov-nikita/nogotochki.git
cd nogotochki
```

Репозиторий закрытый: без доступа на GitHub `git clone` не сработает. Если папка проекта уже есть, этот шаг пропустите и зайдите в неё.

GitHub для HTTPS больше не принимает пароль аккаунта. Если clone спросит пароль — нужен Personal Access Token, вход через GitHub CLI (`gh auth login`) или SSH-ключ, уже добавленный в GitHub.

### 2. Файл настроек

В **корне** репозитория (там же, где папки `server/` и `web/`, не внутри `server/`) скопируйте `.env.example` в `.env`.

PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS / Linux:

```bash
cp .env.example .env
```

Файл `.env` в git не коммитится. Менять значения для первого запуска не нужно: пароли тестовых учёток уже прописаны в примере. Поле `NODE_ENV` оставьте пустым.

### 3. API и база (терминал 1)

```bash
cd server
npm install
npm run db:dev
npm start
```

Дождитесь строки:

```text
nogotochki api listening on http://127.0.0.1:3000
```

`db:dev` создаёт файл `data/nogotochki.sqlite`, накатывает миграции и заполняет тестовые услуги, мастеров и три учётки. Этот терминал не закрывайте.

Проверка API (третий терминал или браузер): http://127.0.0.1:3000/api/health — ответ `{"ok":true}`.

### 4. Тестовая страница (терминал 2)

Из **корня** репозитория:

```bash
cd web
npm install
npm run dev
```

Дождитесь адреса Vite, обычно http://localhost:5173/ . Страницу открывайте **с этого адреса**, не с порта 3000.

Запросы `/api` Vite сам пересылает на API. Cookie и настройка CORS для локального теста не нужны.

## Что открыть и чем войти

| Куда | Зачем |
|---|---|
| http://localhost:5173/ | Тестовый интерфейс (каталог) |
| http://localhost:5173/#/login | Вход |
| http://127.0.0.1:3000/api/health | Только проверка, что API жив |

После `npm run db:dev` (пароли совпадают с `.env.example`):

| Почта | Пароль | Роль |
|---|---|---|
| `client@nogotochki.test` | `DevClient123!` | клиент, кабинет |
| `master@nogotochki.test` | `DevMaster123!` | мастер, своё расписание |
| `admin@nogotochki.test` | `DevAdmin123!` | администратор, ссылка «Админка» |

Страницы тестового UI:

| Адрес | Что делает |
|---|---|
| `#/register`, `#/login` | Регистрация и вход |
| `#/catalog` | Услуги и мастера |
| `#/availability` | Свободное время мастера на дату |
| `#/book` | Резерв слота и подтверждение записи |
| `#/cabinet` | Свои записи, детали, перенос, отмена |
| `#/admin` | Все записи, услуги и мастера (только администратор) |

Ошибки API, в том числе «Это время уже занято», показываются текстом на странице.

## Если не запускается

| Что видите | Что сделать |
|---|---|
| `git clone` просит пароль / Permission denied | Нужен доступ к private-репозиторию; либо откройте уже скачанную папку |
| `node -v` ниже v22.16 или команда не найдена | Установите Node 22.16+ / 24 и откройте новый терминал |
| `npm install` в `server/` ругается на `engines` | Та же причина: слишком старая Node (`engine-strict`) |
| `DEV_ADMIN_PASSWORD must be set` | Нет `.env` в корне репозитория или файл лежит в `server/.env` |
| `seed:dev нельзя запускать при NODE_ENV=production` | В `.env` уберите `NODE_ENV=production` |
| Порт 3000 или 5173 занят | Закройте старый процесс или смените `PORT` в `.env` (тогда фронт всё равно проксирует на **3000** — меняйте оба места только если понимаете зачем) |
| Страница открылась, каталог пустой, вход не работает | API не запущен или не выполнен `npm run db:dev` |
| В DevTools `ECONNREFUSED` / `502` на `/api` | Запущен только Vite, нет `npm start` в `server/` |
| Открыли http://127.0.0.1:3000/ — JSON, не сайт | Это API. Интерфейс — порт **5173** |
| Создание записи отвечает 500 | Локальная база старше кода. В `server/`: `npm run migrate`, затем `npm run seed:dev` |
| Нет ссылки «Админка» | Войдите как `admin@nogotochki.test`, не как client |
| Windows: OneDrive блокирует файл `.sqlite` | Поставьте папку проекта вне синхронизации или сделайте паузу OneDrive |

Полностью пересобрать локальную базу (сотрёт записи): в `server/` выполните `npm run db:reset`, затем `npm run seed:dev`. На сервере с клиентами так делать нельзя.

## Что в папках

| Путь | Назначение |
|---|---|
| `server/` | Express API, порт 3000, `npm start` |
| `web/` | Черновой UI на Vite, порт 5173 |
| `data/` | Файл SQLite, в git не входит |
| `docs/database.md` | Журнал бэкенда, команды БД, таблица маршрутов `/api` |
| `docs/db-schema.md` | Модель таблиц |
| `Паспорт сервиса «Ноготочки».md`, `Путь клиента.md` | Продукт и сценарии |
| `cloud.md` | Бриф для агентов (v0 / Figma / BeGet) |

Корневого `package.json` нет: `npm install` и `npm start` только из `server/` или `web/`.

## Другие команды (из `server/`)

```bash
npm run migrate    # только новые SQL-миграции
npm run seed       # витрина как в паспорте, без тестовых логинов
npm run seed:dev   # тестовые учётки (не для production)
npm run db:setup   # migrate + seed
npm run db:dev     # migrate + seed:dev — обычный локальный старт
npm run db:reset   # удалить локальный файл БД и накатить миграции
npm test           # расчёт окон и сценарии /api
```

Прод бэкенда рассчитан на один процесс Node на BeGet, не на Vercel serverless. Как поднять хостинг — в `docs/database.md`.
