# Cloud — агентный бриф

Документ для ИИ-агентов, которые будут собирать фулстек «Ноготочки». Площадка названа: **v0 (Vercel)**. Не подключай Lovable, не добавляй Stripe, корзину и живую БД, пока человек не попросит следующий срез. Схема SQLite уже согласована в `docs/db-schema.md` — не изобретай другую и не заводи таблицу свободных слотов.

Первый срез — кликабельные переходы лендинг → запись → подтверждение. Промпт: `Промпт переходов записи.md`. Проект в v0 создаёт человек (вставляет промпт сам), агент не обещает `projectId` и публикацию без явной просьбы.

## Стек облака

- **Площадка:** [v0](https://v0.app) (Vercel). Не Lovable.
- **Фреймворк:** Next.js App Router, клиентский прототип.
- **Состояние:** черновик записи в React context + `localStorage` (услуги, мастер, дата, слот, старт резерва, `isLoggedIn`).
- **Auth:** мок-флаг, не Supabase и не OAuth. Вход с шага 4 возвращает на проверку.
- **БД:** в этом срезе не подключать. Когда попросят — SQLite по `docs/db-schema.md`. Таблицы нарезанных слотов нет: окна считаются из графика, записей, блоков и холдов. В первом срезе мастера и окна — моки из паспорта.
- **Оплата:** нет. Stripe, checkout, корзина, промокоды запрещены.
- **UI:** не дефолтный цветной shadcn. Токены и экраны из `figma.md`.
- **Первый промпт:** `Промпт переходов записи.md` — только `/`, `/booking` (шаги 1–5), `/auth` как крюк с шага 4. Каталоги, кабинет, политика, 404 — следующие срезы.
- **Публикация:** только если человек явно попросил выложить превью.

## Как агенту работать

Сейчас:

1. Не создавай проект в v0 и не публикуй, пока человек не вставил промпт сам или не попросил собрать здесь.
2. Дизайн-система и серия экранов в Figma закрыты (`figma.md`, `Путь клиента.md`, `Промпты прототипа.md`). Новых фреймов на `Screens` не добавляй, пока человек не попросит. Регистрация и вход начинаются с лендинга («Войти» в шапке публичных страниц, включая политику), не со степпера; auth-фреймы уже есть — не плодить новые и **не возвращай «Войти» в их шапку**. На шагах 1–3 записи, проверке гостя, служебных и политике «Войти» в шапке оставь. На кабинете — LoggedIn.
3. Фулстек целиком не собирай. Следующий срез — отдельный промпт. Код по `Промпт переходов записи.md`, затем каталоги / кабинет / живая база — только по просьбе. Живую БД подключай строго по `docs/db-schema.md`: не `profiles`, не `slots`.

В v0 и дальше:

1. Одно требование за раз. Не сваливай весь паспорт в один промпт.
2. Спорный подход согласуй, потом кодь.
3. «Агент написал, что сделал» ≠ сделано: проверяй diff и превью v0.
4. Паспортные ограничения, путь клиента и визуал из `figma.md` сразу положи в knowledge чата v0.

## Обязательные продуктовые инварианты

Не нарушай в коде, когда он появится:

- Сайт **не принимает оплату**. Слот резервируется на сайте, предоплату берёт студия вне сервиса.
- Статусы записи: ожидает предоплату / подтверждена / отменена / перенесена / истекла. Нет корзины, Stripe, checkout, промокодов.
- Слот держится ограниченное время. Нужен таймер резерва и сценарии «резерв истёк» / «слот уже занят» → запись с начала.
- Точный адрес — только в кабинете после подтверждения. Публично: «центр города».
- Имя мастера и контакты могут быть пустыми. Не генерировать фейковые ФИО и телефоны. Заголовок: «Мастер студии».
- Нет выезда на дом, нет карты клиента, нет админки в v1.
- Запись требует авторизации (вход / регистрация / восстановление пароля). **Старт входа и регистрации — лендинг** (ссылка «Войти» в шапке публичных страниц), не отдельный «дом» логина и не обязательный пререквизит каталога. На экранах auth в шапке **нет** повторного «Войти» — только форма. Гость может выбрать услуги, мастера и слот; **подтвердить** — только после входа. Черновик и резерв сохраняются (`Путь клиента.md`).
- Дизайн ногтей — добавка к сеансу, не отдельный визит. Подарочный сертификат в прайсе, но **не слот**: не класть в степпер.
- Нестандартные состояния обязательны: пустой кабинет, нет слотов, истёк резерв, слот занят, ошибки входа, потеря сессии (`Empty State / SessionExpired` + «Войти»), 404, сбой сервера. Ошибка входа — `Alert` в форме, не полноэкранный empty. Маппинг на компоненты — в `Путь клиента.md`.

## Экраны, которые нужно собрать (по порядку)

Не начинай с админки и «ещё фич».

1. Публичное: лендинг, каталог услуг, каталог мастеров, карточка мастера с расписанием и «Записаться»
2. Авторизация: вход, регистрация, письмо восстановления, новый пароль, подтверждение смены
3. Запись: услуги → мастер → дата/время → проверка → успех (+ таймер резерва)
4. Кабинет: активные, история, детали, отмена, перенос, профиль (смена пароля), уведомления, правила отмены/переноса
5. Empty/error из паспорта

Авторизация и свободное время — с живой базой по `docs/db-schema.md`, не только моками, как только человек попросит подключить БД. До этого допустим статичный прототип экранов, но не выдавай его за готовый сервис.

Логика шагов, точек входа с лендинга, возвратов и empty/error — `Путь клиента.md`. Последовательные промпты экранов — `Промпты прототипа.md` (один этап за вставку). Допущения оттуда не возводить в факт паспорта: горизонт календаря **8 недель**, резерв стартует **в момент выбора времени** на шаге 3.

## Визуал в коде

Не ставь дефолтный цветной SaaS-шаблон выбранного UI-кита. Повтори систему из `figma.md` (токены как CSS `var(--color-bg-canvas)` и аналоги):

- фон `#FFFFFF` / крем `#F5F3F0`
- акцент-блоки `#F4D7DA` и `#FEE5D8` только под фото, не на кнопках
- Primary — чёрный прямоугольник; Ghost — 1px чёрная обводка (это secondary); Text — без рамки; Danger — `#B42318`, только «Отменить запись»
- заголовки — Playfair Display (или ближайший serif), UI — Inter
- radius 0 / 2px, пилюли запрещены
- русский UI, тон на «вы»
- шапка светлая минимальная, футер чёрный; корзины нет. Публично справа «Войти»; **на страницах входа/регистрации/восстановления ссылки «Войти» в шапке нет** (как в auth-фреймах Figma), чтобы не зациклить вход. Primary «Войти» — только в форме. На служебных 404 / сервер / сессия и на политике — Guest с «Войти».
- пароль — поле с глазом / глазом-перечёркнутым (`Field/Password`), не голый input
- карточка мастера: линия «ближайшее окно» или ряд слотов; нет имени → «Мастер студии»
- степпер записи: 5 шагов (услуги → мастер → дата/время → проверка → готово)
- мобильное меню — оверлей со ссылками Услуги / Мастера / Запись / Кабинет

Спесимены Auth и Slot errors на странице Components в Figma — образец сборки форм и баннеров, не готовые экраны.

## Модель данных

Источник правды схемы: `docs/db-schema.md`. Как это собрано в коде (драйвер, миграции, Node/BeGet): `docs/database.md`. Старый ориентир `profiles` / таблица `slots` со статусами free / reserved / booked **отменён**.

Когда человек попросит подключить БД:

- SQLite, `PRAGMA foreign_keys = ON`. Клиент — `clients`, не `profiles` / `users`. Пароль только `password_hash` (Argon2id или bcrypt), открытого пароля нет. В `sessions` и `password_reset_tokens` — хеш токена, не сам токен.
- Таблицы: `studio_settings`, `studio_closures`, `content_pages`, `content_page_items`, `clients`, `sessions`, `password_reset_tokens`, `services`, `masters`, `master_services`, `master_schedule`, `master_time_blocks`, `booking_holds`, `booking_hold_services`, `appointments`, `appointment_services`, `notifications`.
- Свободное время **не хранится**. Нет `slots` / `time_slots` / `free_slots`. Расчёт в момент запроса: график мастера − записи − `master_time_blocks` − живые холды; плюс `studio_closures` и `min_lead_minutes`. Занятость записи: статусы `pending_prepayment`, `confirmed`, `rescheduled` (не `cancelled` / `expired`). Интервалы полуоткрытые `[start, end)`.
- Резерв до «Подтвердить запись» — `booking_holds` + `booking_hold_services`, не статус записи. После входа и подтверждения появляется `appointments` со статусом `pending_prepayment`. Черновик гостя: `hold_token` можно дублировать в `localStorage`, состав услуг — в БД.
- Статусы записи (код в колонке): `pending_prepayment` / `confirmed` / `cancelled` / `rescheduled` / `expired`. Русская подпись — в UI. Шестого статуса «посещена» нет: прошедшее = время + текущий статус.
- Даты: инстанты — ISO 8601 UTC с суффиксом `Z` (`2026-08-26T07:00:00Z`); календарный день студии — `YYYY-MM-DD`; часы графика — `HH:MM`; пояс — IANA `Europe/Moscow`.
- Факт в одной таблице, в других только внешний ключ (JOIN): не копировать имя мастера, цену, длительность, адрес студии и текст уведомления в запись.
- FAQ, политика, правила, баннер сертификата — `content_pages` + `content_page_items`, не хардкод в пяти местах. Точный адрес — `studio_settings.exact_address`, на экране только при статусе `confirmed`.
- Не храни платёжные реквизиты и колонку «предоплата получена». Факт предоплаты = статус `confirmed`. Клиентский UI статус показывает, платёж не проводит.

Пишущий SQL и ломающие схему команды — только если человек явно попросил. Перед запросом покажи его в чат, после — сколько строк затронуто. Новые таблицы слотов не добавляй, даже «для удобства».
