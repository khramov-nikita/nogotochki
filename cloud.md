# Cloud — агентный бриф

Документ для ИИ-агентов, которые продолжают фулстек «Ноготочки». Продуктовый UI — HTML/CSS/JS в `web/` (MPA, без React и без продуктового бандлера). Vite в `web/` только локально: раздаёт страницы и проксирует `/api` на `:3000`. Живая SQLite — папка `server/` в этом репозитории, прод бэкенда — **BeGet**, не serverless. Не подключай Lovable, Stripe, корзину. Схема в `docs/db-schema.md`, реализация в `docs/database.md` — не изобретай другую и не заводи таблицу свободных слотов. Колонку `clients.role` не добавлять: роли — список в `client_roles` (человек может быть мастером и администратором сразу). Админ не через `ADMIN_EMAILS`.

Правила верстки: `docs/frontend-rules.md`. Карта экранов ↔ API: `docs/ui-map.md`. Папку `server/` не трогай, пока человек не попросил. HTTP только через `web/js/api.js`. Стили — только `var(--…)` из `web/tokens.css`. Узкий экран — только `@media` в `web/responsive.css`, десктопные селекторы не переписывать.

Проект в v0 не создавай и не публикуй. Макеты смотри в Figma, код пиши сюда. HTTP API — `server/src/http/` и `server/src/domain/`; файл БД сам по себе не сервис.

## Стек

- **Продуктовый UI:** обычные страницы в `web/`, не Next.js и не React. Vite — только dev-сервер и прокси `/api`.
- **Бэкенд / прод файла БД:** BeGet, один процесс Node. Не Vercel serverless: SQLite там не живёт.
- **Черновик записи:** `sessionStorage` через `web/js/store.js` (услуги, мастер, дата, `hold_token`). Не React context.
- **Auth:** живые сессии из `sessions` (в БД SHA-256 токена, срок `SESSION_DAYS`), пароль только salted scrypt в `password_hash`. Роли — список в `client_roles`. Login/register с rate limit по `req.ip`; `X-Forwarded-For` только при `TRUST_PROXY` (на BeGet за nginx — `1`, иначе пусто). В теле login/register можно передать `hold_token`.
- **БД:** уже в репозитории. SQLite файл `data/nogotochki.sqlite`, драйвер встроенный `node:sqlite` (`DatabaseSync`), Node **≥ 22.16** (`server/package.json` `engines`). Открытие только через `server/src/db/connection.js`, `PRAGMA foreign_keys = ON`. Схема — 19 таблиц из `docs/db-schema.md` (плюс `roles` и `client_roles`). Таблицы нарезанных слотов нет: окна считаются из графика, записей, блоков и холдов. HTTP API — `server/src/http/` (`npm start` из `server/`). Секреты только в `.env` (в git — `.env.example`); настройки салона — в `studio_settings`, не в env.
- **Команды** (из `server/`): `npm run db:reset` — удалить локальный файл и накатить миграции; `npm run migrate`; `npm run seed` / `seed:dev`. `db:reset` и `seed:dev` не для production.
- **Оплата:** нет. Stripe, checkout, корзина, промокоды запрещены.
- **UI:** не дефолтный цветной shadcn. Токены — `web/tokens.css`, экраны — `figma.md`.

## Как агенту работать

Сейчас:

1. Новых фреймов на `Screens` не добавляй, пока человек не попросит. Регистрация и вход начинаются с лендинга («Войти» в шапке публичных страниц), не со степпера; на auth-страницах **не возвращай «Войти» в шапку**. На шагах 1–3 записи, проверке гостя, служебных и политике «Войти» в шапке оставь. На кабинете — LoggedIn.
2. Не собирай фулстек заново. Не пересоздавай схему, не ставь `better-sqlite3`. Не `profiles`, не `slots`, не колонку `clients.role`. Пароль — `crypto.scrypt`. Не возвращай `ADMIN_EMAILS`.
3. Следующий срез UI — только то, чего ещё нет (см. список ниже), и только по просьбе. Empty того же шага — состояние той же HTML-страницы, не новый файл.
4. `server/` не меняй «заодно с версткой». Нет эндпоинта — скажи человеку.
5. Ошибку API показывай текстом на экране (`error.message`). Свой дедлайн «за 24 часа» не пиши: в сиде `cancel_min_hours_before` / `reschedule_min_hours_before` = `NULL`. «Мало времени» = `can_cancel === false` / `can_reschedule === false` или 409 `CONFLICT`.

Дальше:

1. Одно требование за раз.
2. Спорный подход согласуй, потом кодь.
3. «Агент написал, что сделал» ≠ сделано: проверяй в браузере на http://localhost:5173/ .
4. Перед новым экраном открой строку в `docs/ui-map.md`.

## Обязательные продуктовые инварианты

- Сайт **не принимает оплату**. Слот резервируется на сайте, предоплату берёт студия вне сервиса.
- Статусы записи: ожидает предоплату / подтверждена / отменена / перенесена / истекла. Нет корзины, Stripe, checkout, промокодов.
- Слот держится ограниченное время. Нужен таймер резерва и сценарии «резерв истёк» / «слот уже занят» на тех же страницах степпера, не отдельный HTML «с начала».
- Точный адрес — только в кабинете после подтверждения (`status === "confirmed"` и непустой `exact_address`). Публично: «центр города».
- Имя мастера и контакты могут быть пустыми. Не генерировать фейковые ФИО и телефоны. Заголовок: «Мастер студии».
- Нет выезда на дом, нет карты клиента. Админ-панель появится в следующей итерации.
- Запись требует авторизации, чтобы **подтвердить**. **Старт входа и регистрации — лендинг**, не отдельный «дом» логина. На экранах auth в шапке **нет** повторного «Войти». Гость может выбрать услуги, мастера и слот. Черновик и резерв сохраняются (`Путь клиента.md`).
- Дизайн ногтей — добавка к сеансу, не отдельный визит. Подарочный сертификат в прайсе, но **не слот**: не класть в степпер.
- Нестандартные состояния обязательны: пустой кабинет, нет слотов, истёк резерв, слот занят, ошибки входа, потеря сессии, 404, сбой сервера. Ошибка входа — `Alert` в форме, не полноэкранный empty. Маппинг — в `Путь клиента.md` и `docs/ui-map.md`.

## Модель данных

Источник правды схемы: `docs/db-schema.md`. Как это собрано в коде: `docs/database.md`. Старый ориентир `profiles` / таблица `slots` со статусами free / reserved / booked **отменён**.

Каркас БД уже в `server/`. Когда человек попросит API или правки схемы:

- SQLite через `node:sqlite`, не `better-sqlite3`. `PRAGMA foreign_keys = ON` на каждом соединении. Клиент — `clients`, не `profiles` / `users`. Пароль только `password_hash`: salted `crypto.scrypt` (PHC-строка с N/r/p и солью), не bcrypt и не argon2. Открытого пароля нет. В `sessions` и `password_reset_tokens` — хеш токена, не сам токен. Роли — список в `client_roles`, не колонка `clients.role` и не `ADMIN_EMAILS`. SQL только параметризованный. Ошибки клиенту без текста SQLite и путей. Node на BeGet: **22 LTS ≥ 22.16 или 24**.
- Таблицы: `studio_settings`, `studio_closures`, `content_pages`, `content_page_items`, `clients`, `sessions`, `password_reset_tokens`, `roles`, `client_roles`, `services`, `masters`, `master_services`, `master_schedule`, `master_time_blocks`, `booking_holds`, `booking_hold_services`, `appointments`, `appointment_services`, `notifications`. У мастера-аккаунта — `masters.client_id`.
- Видимость записей — объединение ролей из БД: клиент — свои, мастер — своё расписание, администратор — все. Отмена и перенос — только владелец. Регистрация всегда роль `client`. Login/register режутся по частоте (`req.ip`; `TRUST_PROXY` только за своим nginx).
- Свободное время **не хранится**. Нет `slots` / `time_slots` / `free_slots`. Расчёт в момент запроса: график мастера − записи − `master_time_blocks` − живые холды; плюс `studio_closures` и `min_lead_minutes`. Занятость записи: статусы `pending_prepayment`, `confirmed`, `rescheduled` (не `cancelled` / `expired`). Интервалы полуоткрытые `[start, end)`.
- Резерв до «Подтвердить запись» — `booking_holds` + `booking_hold_services`, не статус записи. После входа и подтверждения появляется `appointments` со статусом `pending_prepayment`. Черновик гостя: `hold_token` можно дублировать в `sessionStorage`, состав услуг — в БД.
- Статусы записи (код в колонке): `pending_prepayment` / `confirmed` / `cancelled` / `rescheduled` / `expired`. Русская подпись — в UI. Шестого статуса «посещена» нет: прошедшее = время + текущий статус.
- Даты: инстанты — ISO 8601 UTC с суффиксом `Z` (`2026-08-26T07:00:00Z`); календарный день студии — `YYYY-MM-DD`; часы графика — `HH:MM`; пояс — IANA `Europe/Moscow`.
- Факт в одной таблице, в других только внешний ключ (JOIN): не копировать имя мастера, цену, длительность, адрес студии и текст уведомления в запись.
- FAQ, политика, правила, баннер сертификата — `content_pages` + `content_page_items` на бэкенде; клиентских GET этих страниц нет — копирайт с макета, без выдуманных штрафов. Точный адрес — `studio_settings.exact_address`, на экране только при статусе `confirmed`.
- Не храни платёжные реквизиты и колонку «предоплата получена». Факт предоплаты = статус `confirmed`. Клиентский UI статус показывает, платёж не проводит.

Пишущий SQL и ломающие схему команды — только если человек явно попросил. Перед запросом покажи его в чат, после — сколько строк затронуто. Новые таблицы слотов не добавляй, даже «для удобства».
